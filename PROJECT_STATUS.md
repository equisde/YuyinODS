# YuyinODS Project Status

This file is written as handoff context for `antigravity-cli` or any other
coding agent resuming work in this repository.

## Current Branch

- Branch: `rebrand-yuyinods`
- Remote: `origin https://github.com/equisde/YuyinODS.git`
- Main project directory: `yuyinods/`
- Root installer entrypoint: `./install.sh`
- Linux installer core: `yuyinods/install-core.sh`

## Current Objective

Verify and harden the installer so it:

- Detects the operator's AMD GPU correctly.
- Configures the installation for that GPU.
- Installs AI models into the configured model directory.
- Keeps Docker data, downloaded models, temp files, and install files under
  `/home/parallax/ODS` or `/mnt/ods`.
- Uses `/home/parallax/ODS` as the default base path; on the target system this
  is a symlink to `/mnt/ods`.
- Makes Docker builds/downloads fast while limiting build pressure to roughly
  80% of CPU and RAM.

## Target Runtime Layout

Default paths generated by the Linux installer:

- App/source install: `/home/parallax/ODS/yuyinods`
- Models: `/home/parallax/ODS/models`
- Temp/logs: `/home/parallax/ODS/temp`
- Docker data root: `/home/parallax/ODS/root-container`
- Container bind-mount data: `/home/parallax/ODS/root-container/data`

The installed app also symlinks:

- `$INSTALL_DIR/data -> $YUYINODS_DATA_DIR`
- `$INSTALL_DIR/data/models -> $YUYINODS_MODELS_DIR`

## What Is Done

### Rebrand

- Root installer banner now shows `YuyinODS`.
- GitHub references were adjusted to `equisde/YuyinODS`.
- Visible installer summary text now uses `YuyinODS` in key places.
- Files and paths were renamed from `ODS`/`ods` to `YuyinODS`/`yuyinods` where
  required by the rebrand work.

### AMD GPU Detection

- AMD APUs with large GTT/unified memory are treated as unified-memory GPUs.
- The detector no longer relies only on the small dedicated VRAM aperture.
- AMD topology detection reports `gfx9012` and effective unified memory.
- Capability profile and runtime selection now choose AMD/Lemonade on this host.

### ComfyUI / Image Generation Guard

- Current bundled AMD ComfyUI image is `gfx1151`-specific.
- This host is `gfx9012`.
- Installer disables ComfyUI/image generation on `gfx9012` to avoid CPU fallback
  and desktop hangs.
- Dry-run no longer lists ComfyUI as a service to start when it has been disabled.
- `ENABLE_IMAGE_GENERATION=false` is forced when ComfyUI is disabled this way.

### Install Paths

- Defaults are based on `/home/parallax/ODS`.
- Models go to `/home/parallax/ODS/models`.
- Temp/logs go to `/home/parallax/ODS/temp`.
- Docker data root goes to `/home/parallax/ODS/root-container`.
- App files go to `/home/parallax/ODS/yuyinods`.
- Background model download task registry now follows `YUYINODS_TEMP_DIR`.
- Preflight report generation falls back to `/tmp` only when the configured temp
  path is not writable, which can happen in the sandbox but should not happen on
  the target machine after the user creates/fixes `/mnt/ods` permissions.

### Build/Download Performance

- `YUYINODS_BUILD_CPU_PERCENT=80`
- `YUYINODS_BUILD_RAM_PERCENT=80`
- `YUYINODS_COMPOSE_PARALLEL_LIMIT` is computed from Docker CPU count.
- `YUYINODS_BUILD_MEMORY_LIMIT_MB` is computed from host RAM.
- Docker compose build runs with:
  - `TMPDIR=$YUYINODS_DOCKER_TMPDIR`
  - `DOCKER_TMPDIR=$YUYINODS_DOCKER_TMPDIR`
  - `COMPOSE_BAKE=false`
  - `COMPOSE_PARALLEL_LIMIT=$YUYINODS_COMPOSE_PARALLEL_LIMIT`
- Builds now attempt `docker compose build --memory ${YUYINODS_BUILD_MEMORY_LIMIT_MB}m`.
- If Compose/BuildKit rejects `--memory`, the installer logs that and retries
  without the memory flag so the install can continue.

### Idempotence

- Local image builds are skipped when the image already exists unless
  `YUYINODS_FORCE_REBUILD=true`.
- Compose startup uses `--no-build` after the explicit build loop.
- Failed optional extension builds can be excluded from compose-up so one failed
  extension does not block the whole stack.

## Known Limitations / Not Complete Yet

- A real install has not been completed in this sandbox because `/mnt/ods` and
  `/home/parallax/ODS` are not writable from the agent sandbox.
- The active goal should not be marked complete until the user runs the installer
  on the host with Docker running and confirms services/models are actually
  installed under `/mnt/ods`.
- Image generation is intentionally disabled on this AMD `gfx9012` host until a
  compatible ROCm/ComfyUI image is added.
- Some helper scripts outside the main Linux install path still use `/tmp` for
  tests, transient reports, or platform-specific installers. Do not treat every
  `/tmp` occurrence as a blocker; focus on Linux installer paths that affect
  Docker builds, model downloads, install files, and persistent temp/log state.
- Dry-run may still print sandbox-specific warnings such as failing to connect to
  systemd bus or falling back to `/tmp` for logs. These are not proof of target
  install failure.
